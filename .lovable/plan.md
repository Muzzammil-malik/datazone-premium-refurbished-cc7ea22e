
# Make DATAZONe fully dynamic with Lovable Cloud

Goal: replace all localStorage/seed data with a real backend so the admin dashboard is the single source of truth, and the public site reflects changes live.

## 1. Enable Lovable Cloud
- Call `supabase--enable` to provision the backend (Postgres + storage + auth).
- Add a `product-images` public storage bucket for product/banner/brand images and video uploads.

## 2. Database schema (one migration)
Tables under `public` (all with proper GRANTs + RLS):

- `categories` (id, name, slug, order, active)
- `brands` (id, name, logo, description, active)
- `products` (id, name, brand, category, processor, ram, storage, gpu, price, original_price, condition, availability, image, tagline, rating, reviews, model, description, display_size, resolution, battery_health, windows, office, charger, slug, meta_title, meta_description, keywords, featured, new_arrival, active, images[], video, created_at)
- `inventory` (id, product_id, serial, supplier, purchase_date, battery_health, ssd_health, qc_status, shelf, status, remarks)
- `inquiries` (id, customer, phone, product_id, product_name, date, source, notes, status)
- `services` (id, title, description, icon, featured, order)
- `reviews` (id, customer, rating, text, date, status, featured)
- `banners` (id, type, image, title, subtitle, cta, link, start_date, end_date, active)
- `homepage` (singleton: hero_headline, hero_subtitle, featured_ids[], why jsonb, testimonial_ids[])
- `settings` (singleton: store_name, logo, favicon, whatsapp, phone, email, address, maps_link, hours, social jsonb, seo jsonb)
- `activity` (id, kind, message, at)

### RLS
- Public read (`TO anon, authenticated USING (true)`) for: products (active only via policy), categories, brands, services, reviews (approved only), banners (active only), homepage, settings.
- `inquiries`: anon INSERT allowed (contact/WhatsApp form), no anon SELECT.
- `inventory`, `activity`: no anon access.
- Since admin has no auth right now, allow `authenticated` full write. To keep the admin working without auth for the current phase, also allow `anon` write on admin-managed tables (documented as temporary). Grants set accordingly.

### Seed
Migration seeds the existing product/category/brand/service/review/banner/homepage/settings rows so nothing appears empty on first load.

## 3. Data layer refactor
- Replace `src/lib/admin-store.ts` (localStorage) with a Supabase-backed store using TanStack Query.
- New `src/lib/api/*.ts` modules: `products.ts`, `categories.ts`, `brands.ts`, `inventory.ts`, `inquiries.ts`, `services.ts`, `reviews.ts`, `banners.ts`, `homepage.ts`, `settings.ts`, `activity.ts` — each exporting `queryOptions` + mutation helpers using the browser Supabase client.
- Delete `src/lib/products.ts` static array; export types + `inr()` only. Product images move to Supabase storage URLs (seed uses current bundled asset URLs re-uploaded, or keeps `/src/assets/*` paths for the seeded rows).
- Replace `useAdmin` calls with `useQuery` hooks; replace `admin.saveX/deleteX` with mutations that invalidate the relevant query keys.

## 4. Public site refactor
- `src/routes/index.tsx`, `shop.tsx`, `product.$id.tsx`, `services.tsx`, `contact.tsx`, `about.tsx`, `warranty.tsx`, footer, nav: read products, categories, banners, homepage, services, reviews, settings from Supabase via loaders (`ensureQueryData`) + `useSuspenseQuery`.
- Contact form + WhatsApp inquiry flow inserts into `inquiries` table.
- Recently viewed / wishlist / cart / compare stay in localStorage (client-only UX state).

## 5. Admin refactor
- Every admin route (`admin.products/categories/brands/inventory/inquiries/services/reviews/banners/homepage/settings/analytics/index`) switches to Supabase queries + mutations.
- Image uploads: add a small `uploadImage()` helper writing to the `product-images` bucket and storing the public URL.
- "Reset admin data" button becomes "Reseed demo data" calling a server function that truncates + re-seeds (optional).

## 6. Cleanup
- Remove all seed arrays and localStorage persistence for domain data.
- Update `SiteChrome`, `Nav`, `Footer` to consume settings from DB.
- Ensure loading/skeleton + empty states on public pages.

## Technical notes
- Uses browser `@/integrations/supabase/client` (publishable key) everywhere — no server functions needed for this phase since RLS handles access.
- Query keys namespaced per table; admin mutations invalidate matching keys so the customer site (open in another tab) picks up on next focus/refetch.
- Types generated by Supabase integration will be used across the app.
